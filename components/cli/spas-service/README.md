# spas-service CLI

Command-line tool for creating, publishing, and pulling SPAS service metadata archives.

## For Users

### Install

```bash
npm install -g @spas/cli
```

### Init

Create a new service workspace with SPAS folder structure and AI agent prompts.

```bash
spas-service init order-service
```

#### Custom output directory

```bash
spas-service init order-service --output ./services
```

#### Force overwrite existing workspace

```bash
spas-service init order-service --force
```

#### Generated Structure

```
order-service/
├── README.md
├── src/
├── metadata/
└── .spas/
    └── schemas/
        └── design-time-metadata-v1.schema.json

.github/
├── agents/
│   └── spas.service.agent.md
└── prompts/
    └── spas.service.prompt.md
```

#### Using the AI Agent

After initialization, invoke the AI agent to scaffold your service:

```
/spas.service NAME:order-service STACK:java CONTEXT:orders
Create a service with CreateOrder command that produces order-created event
```

**Required tokens:**
- `NAME:<id>` - Service identifier (must match workspace folder)
- `STACK:<java|dotnet>` - Technology stack (Java/Spring or .NET)
- `CONTEXT:<name>` - Bounded context for the service

#### 9-Phase AI-Assisted Workflow

The agent guides you through a human-in-the-loop workflow with confirmation gates:

| Phase | Description |
|-------|-------------|
| 1. Analyze | Parse tokens, validate workspace exists |
| 2. Project Structure | Create Maven/Gradle (Java) or .csproj (.NET) |
| 3. Service Metadata | Configure identity, security, license in `spas.json` |
| 4. Storage Layer | Generate repository interface + in-memory implementation |
| 5. Endpoints & Model | Create command/query endpoints with request/response types |
| 6. Events | Define event classes with CloudEvent annotations |
| 7. Sidecar Integration | Wire up SPAS sidecar for event publishing |
| 8. Runtime | Generate Dockerfile and docker-compose.yml |
| 9. Validate | Build project and generate metadata archive |

#### How It Works

1. **Human-in-the-loop**: Agent asks for confirmation before each phase
2. **SDK integration**: Metadata schemas are auto-generated by the SDK at build time
3. **Sidecar-ready**: Generated services integrate with SPAS sidecar for event publishing
4. **Stack-specific**: Agent generates idiomatic code for Java/Spring or .NET

### Publish

#### Publish a locally generated archive

Generate the archive using your SDK, then publish it:

- .NET: [components/sdk/dotnet/README.md](../../sdk/dotnet/README.md)
- Java: [components/sdk/java/README.md](../../sdk/java/README.md)

```bash
spas-service publish --archive ./metadata/service.metadata.zip --repo http://localhost:3000
```

#### From a pre-built archive

```bash
spas-service publish --archive ./order-service-1.0.0.zip --repo http://localhost:3000
```

#### Dry run

Inspects metadata, but does not publish.

```bash
spas-service publish --archive ./metadata/service.metadata.zip --dry-run --output ./archives
```

#### Add runtime image metadata (optional)

```bash
spas-service publish --archive ./order-service-1.0.0.zip \
  --repo http://localhost:3000 \
  --image-repository ghcr.io/myorg/order-service \
  --image-tag 1.0.0 \
  --image-digest sha256:abc123def456...
```

### Pull

```bash
spas-service pull order-service 1.0.0 --repo http://localhost:3000 --output ./archives
```

### Configuration

- `SPAS_REPOSITORY_URL` sets the default repository URL when `--repo` is omitted (default: `http://localhost:3000`).

## Local Development

To use the CLI locally before it's published to npm:

```bash
cd components/cli/spas-service
npm install
npm run build
npm link
```

This makes `spas-service` available globally on your machine. You can now run commands like:

```bash
spas-service init my-service
spas-service publish --archive ./metadata.zip
```

To unlink when done:

```bash
npm unlink -g @spas/cli
```
