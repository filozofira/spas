# SPAS Sidecar

[![Node.js](https://img.shields.io/badge/Node.js-20+-green)](https://nodejs.org/)
[![TypeScript](https://img.shields.io/badge/TypeScript-5.3-blue)](https://www.typescriptlang.org/)
[![License](https://img.shields.io/badge/license-MIT-blue.svg)](../../../LICENSE)

The SPAS Sidecar mediates all service communication in a SPAS domain. It handles event publishing, event subscription, command invocation, and distributed tracing.

## 📦 What is SPAS Sidecar?

The sidecar is deployed alongside each service instance and:

- **Publishes events** to Redis Streams with CloudEvents 1.0 envelope
- **Subscribes to events** and invokes service HTTP endpoints
- **Handles commands** with request-response patterns
- **Propagates traces** via W3C Trace Context and Zipkin
- **Transforms messages** between domain and internal formats

## ✨ Features

- **Event Publishing**: `POST /publish` with topic routing from `x-event-type` header
- **Event Subscription**: Redis Streams XREAD with blocking for event consumption
- **Command Invocation**: `POST /invoke/{command}` for request-response patterns
- **CloudEvents 1.0**: Standard message envelope with trace context extensions
- **Distributed Tracing**: Zipkin span emission with parent-child relationships
- **Health Endpoints**: `/health` and `/ready` for container orchestration

## 🚀 Quick Start

### Prerequisites

- Node.js 20+
- Redis (for message broker)
- Docker (optional, for containerized deployment)

### Installation

```bash
cd components/sidecar
npm install
npm run build
```

### Running

```bash
# Set required environment variables
export CONFIG_PATH=./config.json
export SERVICE_NAME=order-service
export SERVICE_PORT=5001
export REDIS_HOST=localhost
export REDIS_PORT=6379

# Optional: Enable tracing
export ZIPKIN_URL=http://localhost:9411

# Start sidecar
npm start
```

### Development

```bash
npm run dev      # Run with ts-node
npm test         # Run tests
npm run build    # Build TypeScript
```

## 📝 Environment Variables

| Variable       | Required | Default         | Description                         |
| -------------- | -------- | --------------- | ----------------------------------- |
| `CONFIG_PATH`  | Yes      | `./config.json` | Path to sidecar configuration file  |
| `SERVICE_NAME` | Yes      | -               | Target service hostname             |
| `SERVICE_PORT` | Yes      | -               | Target service port                 |
| `REDIS_HOST`   | Yes      | `localhost`     | Redis hostname                      |
| `REDIS_PORT`   | No       | `6379`          | Redis port                          |
| `SIDECAR_PORT` | No       | `7000`          | Sidecar listening port              |
| `ZIPKIN_URL`   | No       | -               | Zipkin endpoint (enables tracing)   |
| `LOG_LEVEL`    | No       | `info`          | Log level: debug, info, warn, error |
| `LOG_FORMAT`   | No       | `text`          | Log format: text or json            |

## 📄 Configuration

The sidecar loads configuration from a JSON file (generated by `spas-compose`):

```json
{
  "inbound": [
    {
      "kind": "event",
      "topic": "orders-requested",
      "transform": "transformOrderEvent",
      "invokeEndpoint": "/incoming"
    },
    {
      "kind": "command",
      "command": "create-order",
      "transform": "transformOrderCommand",
      "invokeEndpoint": "/orders"
    }
  ],
  "outbound": [
    {
      "eventType": "com.example.order.created",
      "topic": "orders-requested",
      "transform": "transformOutboundOrder"
    }
  ]
}
```

## 🔌 API Endpoints

### Publish Event

```bash
POST /publish
Headers:
  Content-Type: application/json
  traceparent: 00-{trace-id}-{span-id}-{flags}
  x-service-name: order-service
  x-event-type: com.example.order.created
  x-correlation-id: {uuid}
  x-user-id: user-123 (optional)
  x-tenant-id: tenant-456 (optional)
Body: { ... event payload ... }
```

### Invoke Command

```bash
POST /invoke/{command}
Headers:
  Content-Type: application/json
  traceparent: 00-{trace-id}-{span-id}-{flags}
Body: { ... command payload ... }
```

### Health Checks

```bash
GET /health  # Liveness: 200 if running
GET /ready   # Readiness: 200 if Redis connected
```

## 🐳 Docker

### Build

```bash
docker build -t spas-sidecar:latest .
```

### Run

```bash
# First, create a config.json file (or use the example)
cp config.example.json config.json

# Linux/macOS
docker run -d \
  -e CONFIG_PATH=/app/config.json \
  -e SERVICE_NAME=order-service \
  -e SERVICE_PORT=5001 \
  -e REDIS_HOST=host.docker.internal \
  -v $(pwd)/config.json:/app/config.json \
  -p 7000:7000 \
  spas-sidecar:latest
```

```powershell
# Windows PowerShell
Copy-Item config.example.json config.json

docker run -d `
  -e CONFIG_PATH=/app/config.json `
  -e SERVICE_NAME=order-service `
  -e SERVICE_PORT=5001 `
  -e REDIS_HOST=host.docker.internal `
  -v ${PWD}/config.json:/app/config.json `
  -p 7000:7000 `
  spas-sidecar:latest
```

### Docker Compose

The easiest way to run the sidecar with all dependencies (Redis + Zipkin):

```bash
# Create config file
cp config.example.json config.json

# Start all services
docker-compose up --build

# Or run in background
docker-compose up -d --build
```

This starts:

- **sidecar** on port 7000
- **redis** on port 6379
- **zipkin** on port 9411 (view traces at http://localhost:9411)

To stop all services:

```bash
docker-compose down
```
